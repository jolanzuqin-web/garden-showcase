# Данные сайта — источник истины и ограничения

Эти JSON-файлы — сгенерированный вывод, не редактируйте их вручную: правки
потеряются при следующей сборке. Источник истины — **`garden-data.xlsx`**
в корне репозитория (листы `Calendar`, `Plants`, `Worktypes`, `Regions`,
`Notes`). Сборка: `node build/build-from-xlsx.js` из папки `docs/build`
(зависимости уже установлены там же через `npm install`).

Старые `vrediteli.txt`/`obrezka.txt`/`udobreniya.txt` и парсившие их
`build/parse-data.js`/`build/build-full-data.js` — предыдущее поколение
пайплайна (regex-парсинг прозы + посезонный сдвиг месяцев для регионов).
Они удалены/не используются: `garden-data.xlsx` содержит уже готовые,
явные строки на каждый регион, без вычисляемого приближения.

## Структура `garden-data.xlsx`

- **Calendar** — region, month, workType, category, plants (через запятую),
  growMethod, text, detail, source (заметка для редактора: откуда взят
  факт/правка — веб-поиск с датой, «авто» для ещё не пересмотренного
  наследия и т.п.; в JSON для сайта не попадает).
- **Plants** — id, name, category, group, hasSeedlingStage, regions
  (где растение типично для региона; пусто = не аудировано отдельно).
- **Worktypes**, **Regions**, **Notes** — зеркало соответствующих JSON.

## Методология регионов

Средняя полоса — базовый, наиболее проработанный регион. Остальные три
региона наполняются по одному через отдельные скрипты
(`build/add-yug-region.js`, `build/add-ural-sibir-region.js`,
`build/add-severo-zapad-region.js`): каждый читает текущие строки средней
полосы, применяет посезонный сдвиг месяцев как черновую заготовку (это
по-прежнему разумное приближение для однолетних овощных культур, где
реальной разницы с средней полосой нет, только сроки), а затем заменяет
записи с настоящей региональной спецификой (не только даты, а другая
техника/культуры/риски) на подтверждённые веб-поиском — с пометкой
источника в столбце `source`. Северо-Запад климатически близок к средней
полосе — сдвига месяцев там нет.

Технический нюанс несимметричного сдвига (весна раньше/позже, осень
позже/раньше): без дополнительной обработки часть месяцев может остаться
совсем без записей (сдвиг увёл всё, что там было, в соседний месяц), а
часть — задвоиться (сдвинутая копия + запасной несдвинутый контент того
же месяца). Каждый региональный скрипт сначала честно заполняет пустые
месяцы несдвинутым контентом, а затем убирает такие дубли по общему
правилу (см. комментарии `dedupFallbackPair` в скриптах регионов) — это
обобщение по нескольким проверенным примерам, а не индивидуальная
проверка каждой пары.

## Что это значит для точности

Для деревьев/кустарников/хвойных и заметных культурных отличий (например,
персик и укрытие винограда на юге, войлочная вишня и стланцевая яблоня на
Урале/в Сибири, клюква на Северо-Западе) — данные подтверждены веб-поиском,
источник указан в `source`. Овощные и ягодные культуры без явной пометки в
`source` всё ещё на приближении «сдвиг месяца от средней полосы» — сроки
разумны, но не выверены индивидуально по региону.

## Как обновить данные

1. Откройте `garden-data.xlsx`, правьте нужный лист напрямую, либо создайте
   узкий скрипт по образцу `build/add-*.js` для пакетных изменений.
2. Запустите `node build/build-from-xlsx.js` из папки `docs/build`.
3. `plants.json`, `worktypes.json`, `regions.json`, `calendar.json`,
   `notes.json` и `bundle.js` перезапишутся.
