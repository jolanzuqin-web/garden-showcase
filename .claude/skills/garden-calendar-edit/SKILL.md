# Правка календаря садовых работ (мультиазентный пайплайн)

Единственный источник истины — **`garden-data.xlsx`**. JSON и
`bundle.<hash>.js` в `docs/data/` генерируются из него, руками не трогаются.
Тот же паттерн ролей, что в `garden-article`: писатель не может сослаться на
факт, которого не проверял агроном.

## Пайплайн

Вызывать субагентов через `Agent` строго по порядку:

1. **`garden-calendar-researcher`** — вход: культура/тип работ/регион + что
   меняем. Выход: JSON `{ region, workType, plants, tezisy, spornye_momenty }`.
2. **`garden-calendar-agronomist`** — вход: JSON от исследователя. Выход:
   JSON `{ approved_tezisy, rejected_tezisy, climate_check_notes }` — источники
   и климатика проверены.
   - Автовозврат: при существенных `rejected_tezisy` — вызвать
     `garden-calendar-researcher` повторно с причиной отказа, максимум 2
     круга, дальше — идти дальше с тем, что одобрено, и пометить пробел.
3. **`garden-calendar-editor`** — вход: `approved_tezisy` + лист/строки для
   правки. Выход: изменённый `garden-data.xlsx` (или новый `add-*.js`),
   заполненный `source`.
4. **`garden-calendar-builder`** — вход: без параметров. Выход: пересобранные
   `docs/data/*.json`/`bundle.*.js` + `git diff --stat` + предупреждение о
   синхронизации со справочником растений, если применимо.

## Перед запуском пайплайна

**Определить, что меняем и на каком листе.** Назначение листов и столбцов —
в [sheets.md](sheets.md). Для точечной правки одной-двух ячеек без спорных
фактов (опечатка, переформулировка без изменения сути) можно пропустить шаги
1–2 и сразу дать `garden-calendar-editor` уточнённую задачу.

## После пайплайна

Показать: `git diff --stat`, что осталось спорным (если есть
`rejected_tezisy`), предупреждение про синхронизацию со справочником от
`garden-calendar-builder`. Если оно есть — **сверка со справочником
обязательна** (см. правило ниже), не оставлять без ответа пользователю.

**Локальная проверка (по желанию):** `node docs/server.js` →
http://localhost:8177/ — открыть нужный месяц/регион.

## Синхронизация со справочником растений

Если затронутая культура есть в `docs/plants-src/<id>.md` — обновить
соответствующий этап жизненного цикла, чтобы формулировки и сроки не
расходились (правило «Синхронизация справочника и календаря» в
`Garden/CLAUDE.md`). Этот пайплайн не делает это автоматически — только
сигнализирует через `garden-calendar-builder`.

## Куда сохраняется результат

- **`garden-data.xlsx`** (+ при необходимости `docs/build/add-*.js`).
- `docs/data/*.json`, `docs/data/bundle.*.js`, `docs/index.html` (хэш bundle)
  — **сгенерированы**, руками не редактировать.
- SEO-снимок в `docs/index.html`/`docs/kalendar/*.html` обновит workflow
  `refresh-calendar-snapshot.yml` после пуша.

## Границы

- Никакой агроправки без веб-подтверждения (`garden-calendar-researcher`) и
  климатической сверки (`garden-calendar-agronomist`).
- Не редактировать JSON/bundle напрямую.
- Не коммитить в рамках этого скилла — это `garden-release`.
